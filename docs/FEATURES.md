# Yapcam feature inventory (reference: Screen Studio 4.0.4-4926)

Columns: `ID | Area | Reference behavior | Source | Yapcam behavior | Team | Status | Evidence | Acceptance test`.
Status is exactly one of: `verified live` · `verified` · `integrated` · `implemented` · `partial` ·
`limited (no hardware)` · `excluded by user` · `extra`. Detail goes in the Evidence column.
- **verified live**: run on the signed app build (launch-flag self-tests or tooling on real recordings) and the outputs checked outside the app.
- **verified**: a named automated test or measurement passed (unit/E2E/native render run), not on a recording made by the app.
- **integrated**: reachable end to end editor -> core -> render, without pixel/real-media proof.
- **implemented**: code present at one layer, not (fully) reachable or proven end to end.
- **partial**: some of the reference behaviour is missing; Evidence says which.
- **limited (no hardware)**: cannot be exercised on this Mac mini M4 (one non-Retina display, no camera, no microphone, no iPhone).
- **excluded by user**: cloud / account / commerce, out of scope by the user's decision.
- **extra**: kept beyond the reference by decision (section M); the row's own status is listed in its section.
- **No row is verified by user interaction.** Round 3 ended without real mouse/keyboard tests (QADriver was never
  granted); every `verified live` row is *programmatic* (the app's own self-test flags, posted events from inside the app).

Source tags: **[observed]** used the installed app · **[docs]** official guide pages ·
**[technical]** file/asset inventory of the installed app (names only, nothing copied) ·
**[assumption]** our inference or design decision.
